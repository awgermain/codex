# Cocktail Codex — project handoff

Reference for continuing work in a new conversation. Records **where things are**,
**why they are that way**, and **what's still open**. The rationale matters more than
the file list — the files are in GitHub and Apps Script; the reasoning isn't anywhere
else.

Keep this in the repo. Supersedes the previous handoff entirely.

**Last updated: October 23 2026** — multi-recipe description fix, new Browse filter
shelf, Explore tiles. See §7a for the description/amount pipeline as it now stands.

**Working conventions with the owner**
- Apps Script sources are mirrored in `apps-script/` in this repo. Claude reads them at
  `https://raw.githubusercontent.com/awgermain/codex/main/apps-script/<file>`; the
  GitHub listing API rate-limits, so the folder page on github.com is the way to see
  file names. The owner pastes changes into Apps Script by hand and refreshes GitHub
  occasionally — **Apps Script is the live copy**; GitHub may lag.
- **Do not add tabs to the sheet.** Reports go in a pop-up (`bShowReport_` in
  BuildAmounts) or a toast. The one exception is `Desc Review`, which needs tick boxes.
- Give the owner one ordered list of steps per change, with the exact menu path.
- Menus can't be built from the editor: `onOpen` / anything calling `getUi()` errors
  when run there. Reload the sheet instead. Scripts that alert fall back to a toast.
- No secrets in the repo: `GH_TOKEN` lives in Script Properties, YouTube uses the
  built-in advanced service (no key). Keep it that way.

## 1. Architecture

```
Google Sheet ──(Apps Script)──> codexdata.js ──(GitHub Pages)──> index.html / menu.html
  Cocktails tab                  published payload               the app
  RC - AmountIndex
  MY BAR
  Add Amount
  Conversion Table
  Audit
```

- **Sheet is the source of truth.** The app never writes back to it.
- **`codexdata.js`** is generated by `publishCodexData` and pushed to GitHub via the
  Contents API. Per-drink keys: `n b s g ga src sn md ts fv mo se ho i fam era r`,
  plus top-level `have`, `units`, `conv`, `untracked`, `gid`.
- **~951 drinks**, ~3,770 amount rows at time of writing.

### Columns resolved by HEADER, never by position
Every script calls `COL('Header')` from `Config.gs`, and ingredient columns come from
`CODEX_ING_GROUPS`. You can insert or move a column in Cocktails freely. The order in
`CODEX_ING_GROUPS` sets the recipe-card order; physical position is irrelevant.

`AuditAmounts` resolves RC headers first-wins, which is only safe because the main
table is leftmost — see §6.

## 2. The ingredient key, and why most bugs live there

`PublishCodex` builds a lookup key as `Name|Ingredient` from the **Cocktails** row,
then reads the amount out of `RC - AmountIndex` **by that key**. Nothing validates the
join. If the stored key does not match — a renamed drink, a retyped ingredient, a
trailing space, a lost `|2` occurrence suffix — the lookup silently returns nothing
and the recipe publishes with no amounts. No error anywhere.

**Every mysterious "the recipe is in the index but shows nothing" bug has been this.**
Three real instances:

- A whole recipe pasted into the **Name** cell, so six amounts filed under
  `Board Shorts\n\n* 2 oz Bourbon…` as the recipe name.
- Six drinks with a **trailing space** in Name. Every other script trimmed; only
  `AmountEntry` did not, so it minted broken keys on every Load. Fixed in v18.
- Ingredients **renamed** after filing — `Bitters` → `Angostura Bitters` — leaving the
  old key stranded.

`auditAmounts` now detects all of these as **orphans** and suggests the correct key in
three confidence tiers. `repairOrphans` applies the two safe tiers.

### 2a. The ingredient library
The other common miss is not the key but the **match**: the sheet says `Amaro`,
`Tequila`, `Lime Juice`, `Amaro Ramazzotti`; the description says `Averna`, `Fortaleza
blanco`, `3/4 oz lime`, `Ramazotti`. `IngredientLibrary.gs` is the one glossary all three
matchers use (it replaced BuildAmounts' 25-entry `SYN`; RecipeBlocks falls back to it).

- Terms = the name, its plural/singular, `ING_LIBRARY` (brands, styles, spellings), and
  derived short forms (`Lime Juice` → `lime`) that carry a **next-word block** so `lime`
  does not fire on `lime wheel` / `lime cordial`, nor `demerara` on `demerara rum`.
- Whole-word matching on normalised text, never substring.
- **One amount, one ingredient.** When two of a drink's ingredients claim a line, the
  earliest match plus anything overlapping it or on the next word compete; longest wins,
  then the narrower ingredient, then the later word. `Hamilton Pimento Dram` → Allspice,
  not Rum as well. Checked against every published drink: 0 of 4,673 lines misassigned.
- Links are stripped from a line, never the line itself (`stripLinks_`). Lines used to be
  dropped whole, which is why linked grenadine / St. Germain went missing.
- **Code only, by choice.** No glossary tab, no menu item -- the owner doesn't want more
  tabs to maintain. Add terms in `ING_LIBRARY`. `glossaryCoverage` (run from the editor)
  lists ingredients that still match on their bare name only.

### One script owns one column
All five tag scripts are **fill-blanks-only**. The sheet wins; type a value and nothing
takes it back. They report disagreements to the log without acting on them. This was a
deliberate reversal — they used to rewrite whole columns.

The implementation detail that matters: the output array must be **seeded from the
current column values** before writing, because `setValues()` writes the whole range.
An empty-seeded array blanks every protected row.

## 4. Known trap: `var` is function-scoped

Two real bugs, same cause, weeks apart:

- `AuditAmounts` declared `var ing = codexIngCols_()` (an array) and pass 2 declared
  `var ing = String(...)` (a name). Same variable. Moving the array declaration above
  pass 2 made the string clobber it, `liveKeys` came out empty, and **every row looked
  like an orphan**. The array is `ingCols` now.
- Same shape in `BuildAmounts` historically.

If something suddenly flags everything or nothing, check for a reused `var` before
anything else.

## 5. CSS traps in `index.html`

Three bugs cost multiple rounds each. All the same shape.

**Specificity ties break on source order.** `.pip.pipstar{margin-right:9px}` lost to
`.chip .pip{margin-right:6px}` declared later — both (0,2,0). Three attempts to change
the number did nothing. Later: `.swm{position:absolute}` lost to `.sheet > *{position:
relative}`, which put the watermark **in the layout** and pushed the recipe down.
Fix: out-specify (`.sheet > .swm`), don't nudge values.

**A dot spec is not a glyph spec.** The favourite star inherited `.pip`, built for a
7px round dot: `display:inline-block`, `vertical-align:1px`. That is why it sat off the
baseline and why its gap never matched the checkmarks. It is `.chipstar` now, mirroring
`.mk-made` exactly.

**`vh` is not the visible viewport on mobile.** `max-height:90vh` on a bottom-anchored
sheet let it grow past the screen, taking the back bar off the top. Use `dvh` with a
`vh` fallback.

Also: `.sheet` was animating, holding rounded corners **and** scrolling. A scroll
container clips to its own `border-radius`. It is now shell + static header + `.sbody`
scroll box. Do not merge them again.

## 6. The Audit tab

One tab, six blocks, each in its own columns so none shift when another changes length.

| cols | block |
|---|---|
| A–I | flags, severity-sorted |
| K–M | progress dashboard + SPARKLINE bars |
| O–P | **ignore list — the only thing you author** |
| R–S | learned ranges |
| U–W | orphan rows, with suggested key and a link |
| Y–Z | composition overlap |

- **Thresholds are learned, not hardcoded** — 5th/95th percentile per category from
  your own data each run, so they never go stale.
- **The ignore list is read before the clear and written back after.** It is user
  content on a tab the script rebuilds.
- **Recipe totals** are checked as well as rows. A per-row check cannot see a recipe
  that is wrong throughout — Sweet Gin Music was 11 fl oz with no spirit and only one
  row tripped. `AUDIT_BIG_STYLES` exempts Punch.
- **No "odd increment" rule, deliberately.** 29 of 36 hits were legitimate thirds.
  A rule that is all false positives teaches you to skim the report.
- `highlightOrphans` is the only thing in the project that paints a data sheet, which
  is why it is a separate menu action and fully reversible.

Google Tables need every column to have a non-empty header and no blank rows inside a
block. Keep it that way.

## 7. Descriptions

The description cell (`YT_Description`) holds **only that drink's recipe**: a title
line, then ingredient lines. The full original is kept in the cell's **note**.

`CleanDescriptions.gs` v2.1:
1. Splits the description into recipe blocks (`RecipeBlocks.gs`) and keeps only the
   block that belongs to this drink, using `recipeLinesFor_` from BuildAmounts so the
   cleaner and the builder always agree.
2. Keeps a line only if it's an **ingredient line**: an amount, a count ("1 whole
   egg"), a short ingredient-only phrase ("Top with Soda Water"), or a short garnish
   line. Sentences go even if they name an ingredient — that loophole is what let
   intros through in v1. Method lines ("Shake and strain") go too, by owner's choice.
3. Title: the block's own, tidied ("THE ENZONI RECIPE 7:10" → "THE ENZONI"); a sentence
   or a decorated section label ("📖 *Recipe(s)* 📖") is never a title; untitled single
   recipes are headed with the drink's name.
4. If the drink's block can't be singled out, the cell keeps **every** recipe, each
   under its own title. If the rules find almost nothing (`CLEAN_MIN_RESULT = 40`), the
   original is kept. `CLEAN_MIN_LENGTH` is now 0 — everything is cleaned.
5. Works **from the note** when one exists, so re-running In Place is always safe and
   repairs earlier output. Notes are written before values and never overwritten.

**`Clear Description Notes` was removed.** The notes are no longer an undo — they're
the copy BuildAmounts falls back to. Don't reintroduce it.

**Order matters: `refetchClippedDescriptions` BEFORE cleaning.** A clipped Shopify blob
is a single line containing measurements, so the cleaner preserves it verbatim and
locks the truncation in. 26 Liber & Co rows were in this state.

**`RC - AmountIndex` column I is a single spilling XLOOKUP in I2**, not a copy.
`BuildAmounts` writes **8 columns** and must never touch I — anything below I2 breaks
the spill.

## 7a. Multi-recipe descriptions → wrong amounts (fixed Oct 2026)

**The bug.** A description holding several recipes (Anders Erickson videos, Make &
Drink two-drink episodes, How to Drink, roundup posts) was parsed as one recipe and each
ingredient took the *first* matching amount anywhere in it. ~40 drinks had another
recipe's amounts (Grapefruit Ginger Margarita had the Frozen Strawberry's lime;
Magician's Descent had Test Pilot's rum; Tiramisu had 4 oz coffee liqueur). Two causes
compounded: `sectionsFor` only recognised a header that *exactly* equalled a drink
name, and CleanDescriptions v1 had stripped every header line from the cell anyway.

**The fix, and the rules that came out of it:**
- `RecipeBlocks.gs` splits text into blocks. A header is a short non-ingredient line
  whose next real line is an ingredient, skipping **any number** of method lines
  ("Build in the blender", "**Recipe Doubled**"). Attribution lines ("By Fanny Chu",
  "Recipe from …") take the line above as the title. Emoji/decoration is stripped
  before deciding a line is a section label. Chapter timestamps are never titles.
- A block is scored for a drink by title match (exact +4, contains +3, token overlap;
  an extra number like "No 2" costs 1.5) plus ingredient overlap. A block whose title
  names a **different** codex drink is never used for this one.
- **BuildAmounts refuses to guess.** Close call (<0.75 margin), weak match (<1), or the
  best block belongs to another drink → that drink gets **no** auto amounts and lands
  in RC - Missing Amount. A missing amount is visible; a wrong one wasn't.
- BuildAmounts reads the **cell** when it holds one recipe of plausible size (cleaned,
  or hand-fixed by the owner), else the **note**. Before v12.2 the note always won and
  hand-corrected cells were ignored.
- `previewBuildAmounts` shows what a rebuild would change in a pop-up, writes nothing.
  Skipped drinks pop up after a real build only if there are any, and drop off once
  all their amounts are filled by hand.
- RC rows sort by recipe, then the app's category order (`CAT_RANK`, keep in step with
  `CAT_ORDER` in index.html), then Occ.

**Desc Review** (`auditMultiRecipeDescriptions`) compares each drink's **RC** amounts
(not the published site — that made fixes look like they hadn't taken) against its own
recipe block. One row per wrong amount, with editable New amount / New unit, an Apply
tick box and a jump link. `applyDescReviewFixes` writes ticked rows to RC and marks them
manual (script writes don't fire AmountGuard, so it sets Source itself). Matching
rules worth keeping: duplicate ingredient rows compare as a set; a line offering
alternatives matches on any of them; whole-word matching ("Ice" ≠ "juice"); float /
rinse / mist rows only match lines that say so; more rows than matching lines → say
nothing. The Source column holds rich-text links whose text is the creator — read
the link, not the value.

**Still true:** if a drink's recipe isn't in its description at all (clipped), nothing
can isolate it — the owner types it into the cell; the note keeps the original.

## 8. The app

### Four tabs: Browse · Build · Explore · My Bar

**Build** was rebuilt. It used to list 224 ingredients alphabetically — everything
equally prominent, which is the same as nothing being prominent. Now:
- a **category shelf** across the top, `CODEX_ING_GROUPS` order, coloured from
  `CAT_COLOR`, each showing how many ingredients still lead somewhere;
- a **ranked pairings list** below, ordered by how many matching drinks each
  ingredient opens, with a bar for how many you can make tonight;
- selected rows stay **lit in place** rather than vanishing to a pill.

**Explore** has one wide "ready tonight" tile (quiet bar, number is the message) and
five peers: Untried (hollow ring), Made (✔), Shortlist, Favorites, Originals. Every big
number means *ready*; the faint `/N` beside it is the size of that set. Tiles jump to
Browse with the matching Marks. Then nine collapsible sections ordered by the *kind* of question:
what it is (Base Spirit, Style, Family, Era), when you would drink it (Served, Mood,
Season, Holiday), where it came from (Creator). Every row jumps to the existing Browse
filter — no parallel filtering logic.

**Search** sits below the tabs on every tab. In Explore it narrows the *sections*
(matching rows open, others hide, the Creator cap lifts). In Build, picking an
ingredient clears the search and jumps the shelf to that ingredient's category; tapping
a category also clears it. A ✕ in the box clears it anywhere. In My Bar it auto-opens
matching groups.

**Build** results now have their own collapsible head ("Drinks with Lemon Juice + …",
count, "top 60" when capped). The category shelf is a wrapping grid
(`auto-fill, minmax(92px,1fr)`), not a sideways scroll.

**Browse filters** are a shelf of ten tiles, five across, grouped by colour: what it is
(brass: Spirit, Style, Family, Era), who made it (mauve: Creator), when (blue: Served,
Mood, Season, Holiday), yours (muted: Marks). One line per tile; picks summarise as
"Bourbon +1"; the pill row above is the full record. Tapping a tile opens its values as
two ranked columns with readiness bars and **faceted** counts (given every other
filter). Head row folds the whole shelf; value list folds and sorts Most used / A–Z.
- One model: `FCATS` + a Set per category (`fsel`). Across categories AND; within a
  one-per-drink category OR; Mood and Season get an Any/All toggle at two picks;
  Marks always AND (they're qualifiers: Ready, Untried, Made, Shortlist, Favorite,
  Original).
- **Spirit means the base spirit** (`d.b`, one per drink). "Has rum and cognac in it"
  is Build's job — deliberately not duplicated in Browse.
- American spelling in UI text ("Favorite", "color").

### Rules worth not relitigating
- **`_stock` excludes untracked categories** (`Other`, `Muddled`); `_set` is display
  only. Confusing the two once misclassified 93 drinks. Everything routes through
  `HAVE_SET()`.
- **One mark, two facts.** Colour is the category, fill is stock. Used on recipe rows
  and in Build. Do not add a second dot.
- **Colour tiers mean one thing everywhere**: green ≥67%, brass 34–66%, red below.
  Card stripes, Explore bars, Build bars, audit sparklines.
- **Display and arithmetic are separate.** Dashes, tsp and tbsp display natively but
  carry a volume via `COUNT_ML` / `NATIVE_UNITS`, so totals and percentages stay right.
  `1 tsp` shows as `1 tsp`, counts as 0.167 fl oz.
- **Units are stored singular; the app pluralises** from the quantity. `1 dash` and
  `2 dashes` come from the same stored value.
- **Counts are in the batch total**, so 1000 g means 1000 g. Vieux Carré used to make
  1049 g because the bitters were added on top of a split that already summed.
- **Egg is per-drink**, never batched.
- **The liquid total excludes count units** for display only — one dash of bitters
  turned 3.25 into 3.284, which reads like a typo.

### Owner-only edit links
`?sheet=<id>` once, stored in localStorage, never in the repo. Tab gids come from the
published payload (`gid.c`, `gid.rc`) because a row number is ambiguous without one.
`?sheet=off` to disable; an empty value is a deliberate no-op.

## 9. Open

**Tabled by the owner**
- Custom-recipe table (ex-"Preps") in free columns of `RC - AmountIndex` from Z.
  Needs **distinct headers** — `Recipe`, `Ingredient`, `Amount`, `Unit`, `Category` are
  already duplicated across that tab and `auditCols_` resolves first-wins.
